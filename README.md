# console_widgets

Небольшая учебная библиотека TUI-виджетов для терминала на C++17 и ncurses.
Проект вырос из ручного меню и постепенно превращается в переиспользуемую
основу для консольных приложений.

Репозиторий: <https://github.com/hovrah888/TUI_widgets_ncurses>

## Возможности

- RAII-обёртка над ncurses: терминал инициализируется и восстанавливается сам.
- Единая палитра цветов (`hcm::InitTheme`).
- Типобезопасные клавиши (`hcm::Key`) и результат обработки (`hcm::Result`).
- Виджеты: `Button`, `Label`, `CheckBox`, `TextField`, `List`.
- Меню с вертикальной навигацией и вложенными списками.
- Безопасный разбор чисел в `TextField` (`ParseInt`) без исключений.
- Два примера: `demo` — витрина виджетов, `example1` — калькулятор.

## Требования

- Компилятор с поддержкой **C++17** (проект использует `std::from_chars`).
- **CMake 3.16+**.
- **ncurses** с заголовочными файлами.
- macOS или Linux, терминал с поддержкой цветов (без цветов библиотека тоже
  работает, просто рисует монохромно).

Установка ncurses на Debian/Ubuntu:

```sh
sudo apt install libncurses-dev
```

На macOS ncurses входит в состав системы.

## Сборка

### CMake

```sh
cmake -S . -B build
cmake --build build --parallel
```

`CMAKE_EXPORT_COMPILE_COMMANDS` уже включён в `CMakeLists.txt`, поэтому после
конфигурации появляется `build/compile_commands.json` для clangd и VS Code.

Собираются три цели:

| Цель | Исходники | Что это |
|---|---|---|
| `hcm` | `hcm.cpp`, `hcm.h` | статическая библиотека виджетов |
| `demo` | `main.cpp` | витрина виджетов |
| `example1` | `example1.cpp` | калькулятор |

### Вручную, без CMake

macOS:

```sh
clang++ -std=c++17 main.cpp hcm.cpp -o demo -lncurses
clang++ -std=c++17 example1.cpp hcm.cpp -o example1 -lncurses
```

Linux:

```sh
g++ -std=c++17 main.cpp hcm.cpp -o demo -lncurses
```

На некоторых дистрибутивах Linux дополнительно нужен `-ltinfo`. На macOS
отдельной библиотеки `tinfo` нет, `-lncurses` достаточно.

`-std=c++17` обязателен: при `-std=c++11` или `-std=c++14` компилятор сообщает,
что `std::from_chars` и `std::from_chars_result` не существуют.

### Сборка с санитайзерами

```sh
cmake -S . -B build-asan -DHCM_SANITIZE=ON
cmake --build build-asan --parallel
./build-asan/demo
```

Опция `HCM_SANITIZE` включает AddressSanitizer и UndefinedBehaviorSanitizer.

## Запуск

```sh
./build/demo
./build/example1
```

`demo` показывает все виджеты и два экрана: корневое меню и справку.
`example1` — калькулятор: два текстовых поля, `Label` с результатом и кнопки
`Sum`, `Sub`, `Mul`, `Div`, `EXIT`.

## Управление

| Действие | Клавиши |
|---|---|
| Вверх | `k` или `↑` |
| Вниз | `j` или `↓` |
| Влево | `h` или `←` |
| Вправо | `l` или `→` |
| Выбрать | `Enter` или `Space` |
| Назад | `Esc` или `x` |
| Выйти из приложения | `q` |

`q` работает из любого экрана, даже когда открыт вложенный список.

### Поведение по приложениям

- **demo**: `Esc` на экране справки возвращает в корневое меню, `Esc` на
  корневом экране завершает приложение. Кнопка `Exit` делает то же самое.
- **example1**: любое событие, кроме `Continue` (то есть `Esc`, `x` или `q`),
  завершает цикл и приложение.

Библиотека не решает, что означает «назад»: `Menu::HandleKey` возвращает
`Result::Close`, а приложение само выбирает реакцию.

### Текстовое поле

- `Enter` на поле запускает ввод, приглашение печатается строкой ниже.
- Длина ограничена `maxLength` (по умолчанию 64 символа).
- `Enter` подтверждает ввод; пустой ввод возвращает placeholder.
- `Esc` не отменяет ввод (это ограничение `getnstr`): управляющие символы
  вырезаются из результата, значение остаётся тем, что было напечатано.
- `ParseInt()` возвращает `fallback` (по умолчанию `0`) для пустой строки,
  мусора и переполнения. Исключений нет.

### Список

- `Enter` или `Space` на закрытом списке открывает его.
- Внутри списка `j`/`k` или стрелки перемещают выделение.
- `Enter` активирует выбранный элемент.
- `Esc` закрывает список.
- Первый элемент списка — служебный `(X) Close list`: он тоже закрывает список.

## Устройство библиотеки

### Пространства имён

В `namespace hcm` находятся:

- `hcm::Key`, `hcm::Result`;
- `hcm::Terminal`;
- `hcm::InitTheme()`;
- `hcm::ReadKey()`.

Виджеты (`Widget`, `Button`, `Label`, `CheckBox`, `TextField`, `List`, `Menu`)
пока объявлены в глобальном пространстве имён. Это историческое состояние;
унификация запланирована в P1.

### Жизненный цикл терминала

```cpp
hcm::Terminal term;
if (!term.Valid()) {
    return 1;
}
hcm::InitTheme();
```

`Terminal` создаёт объект в начале `main` и вызывает `endwin()` в деструкторе.
Поэтому ручной `endwin()` не нужен: терминал восстанавливается и при обычном
выходе, и при размотке стека из-за исключения. `Valid()` возвращает `false`,
если `initscr()` не смог инициализировать экран.

Конструктор также:

- выставляет `ESCDELAY=25`, чтобы одиночный `Esc` не «залипал» на секунду;
- включает `cbreak()`, `noecho()` и `keypad(stdscr, TRUE)`;
- скрывает курсор.

`Terminal` нельзя копировать и перемещать: два объекта означали бы два
`initscr()`/`endwin()` на один терминал.

### Клавиши и результат

`hcm::ReadKey()` читает ровно одно нажатие через `getch()` и переводит его в
`hcm::Key`:

```cpp
enum class Key {
    None, Up, Down, Left, Right,
    Select, Back, Quit, Resize, Unknown
};
```

`Menu::HandleKey(Key)` возвращает `hcm::Result`:

```cpp
enum class Result {
    Continue,  // меню продолжает работу
    Close,     // пользователь просит закрыть это меню (Esc)
    Quit       // пользователь просит выйти из приложения (q)
};
```

Библиотека сообщает, что случилось, а решение принимает приложение.

### Виджеты

Базовый класс:

```cpp
struct Widget {
    virtual void Show(bool selected = false, int y = 0) = 0;
    virtual void OnSelect() {}
    virtual ~Widget() = default;
};
```

| Виджет | Назначение | `OnSelect()` |
|---|---|---|
| `Button` | кнопка с лямбдой | вызывает лямбду |
| `Label` | текст, `SetText()` | ничего |
| `CheckBox` | флажок | переключает состояние |
| `TextField` | ввод строки и `ParseInt()` | запускает ввод |
| `List` | раскрывающийся список | открывает/закрывает |

`Menu` хранит `std::vector<Widget*>`, рисует заголовок и виджеты, а также
делегирует клавиши открытому `List`.

### Владение

`Menu` и `List` владеют добавленными виджетами и удаляют их в деструкторе.
Поэтому они **не копируются и не перемещаются**:

```cpp
Menu(const Menu&) = delete;
Menu& operator=(const Menu&) = delete;
Menu(Menu&&) = delete;
Menu& operator=(Menu&&) = delete;
```

Копирование привело бы к двум `delete` на одни и те же указатели. Сейчас
владение ручное; переход на `std::unique_ptr` запланирован в P1.

### Минимальное приложение

```cpp
#include "hcm.h"

int main() {
    hcm::Terminal term;
    if (!term.Valid()) {
        return 1;
    }
    hcm::InitTheme();

    bool running = true;

    Menu menu(" HELLO ");
    menu.widgets.push_back(new Label("Hello, ncurses!", 5));
    menu.widgets.push_back(new Button("Exit", [&running]() { running = false; }, 6));

    while (running) {
        menu.Show();
        if (menu.HandleKey(hcm::ReadKey()) == hcm::Result::Quit) {
            running = false;
        }
    }
    return 0;
}
```

### Главный цикл

Порядок важен: сначала рисуем кадр, потом ждём клавишу. Поэтому после каждого
ввода экран перерисовывается с новым выделением.

```cpp
while (running) {
    currentMenu->Show();
    switch (currentMenu->HandleKey(hcm::ReadKey())) {
        case hcm::Result::Quit:
            running = false;
            break;
        case hcm::Result::Close:
            // приложение само решает, что значит «назад»
            break;
        case hcm::Result::Continue:
            break;
    }
}
```

### Цвета

`hcm::InitTheme()` инициализирует восемь пар. Номера — временное решение,
в P2 они станут именованными стилями.

| Пара | Текст | Фон | Где используется в примерах |
|---|---|---|---|
| 1 | magenta | cyan | заголовок меню |
| 2 | black | yellow | кнопки действий |
| 3 | white | cyan | текстовое поле |
| 4 | white | green | чекбокс, список |
| 5 | yellow | white | подписи и элементы списка |
| 6 | black | red | выход, закрытие списка |
| 7 | magenta | blue | фон экрана (`bkgd`) |
| 8 | black | magenta | кнопка справки |

Использование конкретных пар — соглашение примеров, а не требование
библиотеки. На монохромном терминале `InitTheme()` ничего не делает.

## Ограничения

Это учебный этап, а не финальное API. Известные ограничения:

- владение виджетами ручное (`new`/`delete`), без `std::unique_ptr`;
- `Menu` использует `dynamic_cast<List*>` для раскрытых списков;
- виджеты живут в глобальном пространстве имён;
- координаты и отступы захардкожены (`y = 3`, `x = 5`);
- цвета задаются номерами пар 1–8;
- у списков нет прокрутки: длинный список выйдет за пределы экрана;
- `TextField` построен на `getnstr`: нет перемещения курсора, редактирования
  середины строки и отмены по `Esc`;
- `KEY_RESIZE` только вызывает перерисовку, без пересчёта раскладки;
- нет юнит-тестов и CI;
- нет `install`/`export`, поэтому библиотеку нельзя подключить как пакет.

## План развития

### P1 — владение и архитектура

- `std::unique_ptr<Widget>` и `std::vector<std::unique_ptr<Widget>>`.
- Убрать `dynamic_cast<List*>` из `Menu` (виртуальные методы или visitor).
- Сделать `widgets` и `selectedIndex` приватными, добавить аксессоры.
- Перейти к правилу нуля: без ручных деструкторов и `= delete`.
- Переместить виджеты в `namespace hcm`.

### P2 — раскладка и внешний вид

- `Rect` / `Surface` и нормальный layout вместо магических координат.
- Именованные стили вместо цветовых пар.
- Прокрутка списков и корректная подрезка выделения.
- Осмысленная обработка `KEY_RESIZE`.
- Собственный построчный редактор для `TextField`.
- Более безопасное деление в примере (`std::optional<int>` вместо проверки
  на месте вызова).
